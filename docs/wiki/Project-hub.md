## What each space means

The **website and wiki** teach the current node. Their guides come from the
same versioned Markdown, so a useful correction improves both places.

**Discussions** are for questions, examples, and early ideas. **Issues and
pull requests** track specific, reviewable changes. A suggestion is not an
accepted feature until its scope has been reviewed.

The **project board** shows priorities and progress. Done work links to a
release or a deployed documentation change. Considered ideas have no promised
date or version. The **changelog** records software releases; website changes
can ship separately without creating a new node version.

**GitHub releases and the Registry** distribute the node. The Registry may
take time to process a new version. The release assets and the website have
separate signed build provenance. That signing does not certify generated
images or guarantee recognition by Civitai's own parser.

## One shared set of expectations

CiviScribe stays focused on current ComfyUI image saving. PNG, JPEG, and WebP,
truthful resource identities, image fidelity, safe output paths, and
pixels-first saving remain the product boundaries. Broader filesystem access
and adapters for other applications remain separate design decisions.

Review attachments for private prompts, workflows, paths, images, and
credentials. Use the private reporting route for vulnerabilities. The
[community guidelines](https://github.com/chriscollins500/ccollins-civiscribe/blob/main/CODE_OF_CONDUCT.md)
apply across the project spaces.
