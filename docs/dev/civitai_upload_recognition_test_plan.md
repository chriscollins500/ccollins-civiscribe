# Civitai Upload Metadata Recognition Test Plan

## Purpose

This controlled harness helps determine which PNG metadata fields Civitai uses to populate `Resources Used`, especially for VAE/resource recognition.

A real 0.9.15 upload showed Civitai displaying a VAE even when the node did not emit that VAE as a final A1111 `Civitai resources` entry. That observation is useful, but it does not prove whether Civitai used A1111 `Hashes`, the ComfyUI workflow, the custom `civitai` manifest, or another parser path.

Use these variants to compare one parser source at a time. Do not infer parser source from a screenshot alone. Infer source only from differences between variants made from the same source PNG.

## Tool

```text
python tools/make_civitai_metadata_recognition_variants.py path/to/source.png
```

Optional output folder:

```text
python tools/make_civitai_metadata_recognition_variants.py path/to/source.png --output-folder recognition_test
```

The source PNG should be generated by `Save Image with Civitai Metadata`.

The tool does not call the network. It writes PNG copies with identical pixels and controlled metadata. It also writes:

- `recognition_variants_manifest.json`
- `recognition_variants_manifest.csv`

Use either manifest as the manual worksheet.

## Variants

| Variant | Metadata Included | Purpose |
| --- | --- | --- |
| `A_full_baseline` | Source PNG copied byte-for-byte. | Baseline: confirms current real upload behavior. |
| `B_a1111_hashes_only` | `parameters` tEXt with `Model hash`, `VAE hash`, and `Hashes`; no prompt/workflow/civitai iTXt; no A1111 `Civitai resources`. | Tests A1111 hash-only recognition. |
| `C_workflow_and_manifest_only` | Resource-bearing A1111 fields stripped; `workflow` iTXt and `civitai` iTXt kept. | Tests ComfyUI workflow plus custom manifest. |
| `D_workflow_only` | Resource-bearing A1111 fields stripped; `workflow` iTXt kept; `civitai` iTXt removed. | Tests Civitai's ComfyUI workflow parser. |
| `E_civitai_manifest_only` | Resource-bearing A1111 fields stripped; `workflow` iTXt removed; `civitai` iTXt kept. | Tests whether Civitai reads this node's structured manifest. |
| `F_no_resource_metadata` | No `parameters`, no `workflow`, no `civitai`; only pixels and `Software`. | Negative control. |
| `G_a1111_model_hash_only` | `parameters` tEXt with `Model hash` and `Hashes` model entries only. | Tests base model hash-only recognition without VAE hash. |
| `H_explicit_civitai_resources_only` | `parameters` tEXt with A1111 `Civitai resources` only; no `Hashes`, `Model hash`, or `VAE hash`. | Tests explicit resource parsing. |
| `U_exif_usercomment_full_only` | PNG `eXIf` / EXIF `UserComment` only. | Tests Civitai-style EXIF UserComment recognition without PNG text/iTXt metadata. |
| `V_parameters_plus_exif` | `parameters` tEXt plus PNG `eXIf` / EXIF `UserComment`; no workflow/civitai iTXt. | Tests combined A1111 and EXIF behavior without ComfyUI workflow or custom manifest. |
| `W_exif_resources_only` | EXIF `UserComment` containing only `Civitai resources`. | Tests EXIF explicit resources parsing. |
| `X_exif_civitai_metadata_only` | EXIF `UserComment` containing only `Civitai metadata`. | Tests whether Civitai reads resources/settings from EXIF metadata JSON. |
| `Y_exif_minimal_no_resources` | EXIF `UserComment` with resource-bearing fields stripped. | Negative control for EXIF metadata without explicit resource fields. |

For variants that keep `parameters`, the tool writes it as classic PNG `tEXt`. For variants that keep `workflow` or `civitai`, the tool writes them as uncompressed UTF-8 `iTXt`. For EXIF variants, the tool writes PNG `eXIf` with EXIF `UserComment` encoded as `UNICODE` UTF-16BE.

## Manual Upload Steps

1. Generate one source PNG with the normal save node.
2. Run the variant tool on that source PNG.
3. Upload only one variant at a time to Civitai.
4. Record the upload result in `recognition_variants_manifest.csv` or `.json`.
5. Remove or clearly label each test upload after recording results to avoid confusing real posts.
6. Keep the source and variants together so every observation maps back to the same image pixels.

## What To Record From Civitai UI

For each variant, record:

- Prompt detected?
- Negative prompt detected?
- Base model displayed?
- VAE displayed?
- LoRAs displayed?
- Exact Resources panel entries.
- Exact Other Metadata panel entries.
- Workflow Nodes button present?
- Any warning/error shown by the upload page.

Screenshots are useful for audit trails, but they are not proof of parser source by themselves.

## Optional API Verification

If an image ID or post ID is available after upload, optionally query Civitai:

```text
GET /api/v1/images
```

Record:

- returned `meta.resources`
- returned `meta.hashes`
- returned prompt/settings fields

Only use public image/post IDs from your own test upload. Do not send local files, prompts, workflows, sidecars, local paths, or tokens through this harness.

## Interpretation Rules

- If the VAE appears in `B_a1111_hashes_only` but not in `G_a1111_model_hash_only`, that supports VAE hash recognition from A1111 fields.
- If resources appear in `D_workflow_only`, that supports ComfyUI workflow parsing.
- If resources appear in `E_civitai_manifest_only`, that supports Civitai reading this node's structured manifest.
- If resources appear only in `H_explicit_civitai_resources_only`, that supports explicit A1111 `Civitai resources` parsing.
- If resources appear only in `U`/`W`/`X`, that supports Civitai reading EXIF `UserComment` rather than the PNG text/iTXt layers.
- If resources appear in `F_no_resource_metadata`, the test is contaminated or Civitai is using something outside these metadata fields.
- If the baseline differs from every controlled variant, repeat the test with a fresh upload before changing production behavior.

Do not change production save behavior from a single screenshot. Change production behavior only after controlled variants identify the parser source.

## Local Verification

Check variant chunk layout with:

```text
python tools/inspect_png_chunks.py path/to/variant.png
```

Expected highlights:

- `parameters` is `tEXt` where present.
- `workflow` is `iTXt` where present.
- `civitai` is `iTXt` where present.
- `eXIf` is present for EXIF variants.
- CRCs are valid.
- Pixels match the source PNG.

The unit tests cover these invariants for a fixture image.
